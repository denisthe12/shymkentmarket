# SCRUM-25: раздел «СЗПТ» — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Раздел «СЗПТ»: 10 групп продуктов по критериям приказа № 362-нқ, у каждого товара цена упаковки и цена за кг / л / 10 шт, фильтр фасовки и две сортировки на сервере.

**Architecture:** Новый read-only API `/api/szpt` и `/api/szpt/{group}/products` в Go поверх существующих `canonical_products`/`offers` текущего снапшота. Правила групп — один Go-список, который передаётся в SQL параметром (`jsonb_to_recordset`), без миграций. Фронт — страницы `/[lang]/szpt/[group]` и плитка в каталоге; выходит отдельным PR только после релиза API.

**Tech Stack:** Go 1.27.4 (chi, pgx v5, PostgreSQL 17), OpenAPI 3.1 + Redocly + ajv (`contracts/`), Next.js 16 / React 19 / TanStack Query / vitest / Playwright (`frontend/`).

**Spec:** `docs/superpowers/specs/2026-11-12-scrum-25-szpt-design.md`

## Global Constraints

- Существующие `/api/products`, `/api/categories`, `/api/categories/{slug}/filters`, `/api/dashboard`, Voice и их DTO не меняются ни по поведению, ни по формату.
- Никаких миграций и изменений в `backend/prisma`; publish scope и pipeline не трогаются.
- Состав и порядок групп ровно: `rice, buckwheat, sour-cream, cottage-cheese, cheese, milk, kefir, sunflower-oil, eggs, butter`.
- Единицы: `kg` и `l` — множитель 1000, `10pcs` — множитель 10. Для `milk` и `kefir` размер = `volumeMl`, иначе `weightGrams` (1 г = 1 мл).
- `unitPrice.value` округляется до 2 знаков half-up только в ответе; сортировка — по точному значению в SQL.
- Сортировки СЗПТ: `price_asc` (по умолчанию) и `unit_price_asc`; при равенстве — `min_price`, затем `id COLLATE "ru-x-icu"`.
- Регулярки PostgreSQL `~*` без `\b`, `\m`, `\M`; граница слова — классом `[^а-яё]`.
- Фронт ничего не считает, только форматирует; без `unitPrice` строки цены за единицу нет (ни «0 ₸/кг», ни прочерка).
- Фронт: перед кодом прочитать нужные гайды в `frontend/node_modules/next/dist/docs/` (правило `frontend/AGENTS.md`).
- PR 1 (Tasks 1–4: контракт и API) и PR 2 (Tasks 5–8: фронт) — разные ветки; PR 2 мержится только после релиза API (Task 10).
- Перед каждым push: `MSYS_NO_PATHCONV=1 node C:/Development/AdilBaga-local-ci/run-local.mjs` — все группы зелёные. Сам инструмент не коммитить.
- Прод (Tasks 9–13): каждое действие на проде — только после явного «да» пользователя в чате. Команды на VPS вводит пользователь; агент к VPS не подключается и секреты не читает.

## Review Focus

1. Буквы `ё`/`е` и капс в названиях («СЫР Голландский», «Масло … несолёное», «Молоко топлёное») классифицируются так же, как строчные. Тест — Task 3, `TestDeterministicSzpt/membership` (строки фикстуры с капсом и `ё`).
2. Если у товара предложения в нескольких сетях, у каждого предложения своя `unitPrice`, а `unitPrice` товара берётся от самого дешёвого предложения. Тест — Task 3, подтест `offer unit prices`.
3. Нечисловые и «странные» значения `size`: `abc`, `-1` и `1e3` → 400. `1000.0` при опциях `[1000]` проходит: сравнение числовое. Тест — Task 4, `TestParseSzptQuery`.
4. В снапшоте нет ни одной группы: `/szpt` отдаёт 404, а не крутится в цикле редиректов, и плитки в каталоге нет. Тест — Task 7 (`SzptIndex` с пустыми группами) и Task 8 (`CategoryTiles` без групп).

SQL (одна константа `szptBaseSQL`, параметры передаются, а не склеиваются):
- `$1` — `json.Marshal(szpt.Groups)`, разбирается `jsonb_to_recordset($1) AS g(slug text, category text, size_keys text[], min_size numeric, include text[], exclude text, fat_min numeric, fat_max numeric)`;
- `$2` — `snapshotID`.
- CTE `usable` — как в `dashboardSQL`: товары с `o."inStock" AND o.price>0` в снапшоте `$2`, `min_price`, `max(snapshotAt)`.
- CTE `members`: `usable` × `g` по `c.slug=g.category`.
  - `size` — первое числовое значение из `g.size_keys` по порядку (`unnest … WITH ORDINALITY`, `jsonb_typeof='number'`).
  - Условия:
    - `size >= g.min_size`;
    - все `include` совпадают: `NOT EXISTS (SELECT 1 FROM unnest(g.include) i WHERE NOT p.name ~* i)`;
    - `g.exclude = '' OR NOT p.name ~* g.exclude`;
    - если `g.fat_min IS NOT NULL` — `jsonb_typeof(attributes->'fatPercent')='number'` и значение `BETWEEN g.fat_min AND g.fat_max`.
- `ListGroups`: `SELECT slug, count(*), array_agg(DISTINCT size ORDER BY size) FROM members GROUP BY slug`.
- `ListSzptProducts`:
  - строки `members` для `g.slug=$3`; `$4::numeric[]` — пустой массив = без фильтра, иначе `size = ANY($4)`;
  - сортировка — статический фрагмент по `q.Sort`:
    - `price_asc`: `ORDER BY min_price, id COLLATE "ru-x-icu"`;
    - `unit_price_asc`: `ORDER BY min_price::numeric*$7/size, min_price, id COLLATE "ru-x-icu"` (`$7` — `Unit.Factor()`);
  - `LIMIT $5 OFFSET $6`;
  - колонки как у `productBaseSQL` + `size`.
  - Затем `attachOffers`, затем в Go: `UnitPrice` товара = `PriceOf(MinPrice, size, unit)`, у каждого предложения — `PriceOf(o.Price, size, unit)`.
- Проверка `size`: перед выборкой тот же `members` для группы даёт список размеров; каждое значение `q.Sizes` должно совпасть численно, иначе `ErrInvalidQuery`. Оба запроса — через один `snapshotReader`.
