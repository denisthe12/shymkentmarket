# Удаление C2: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Если этих скиллов нет (агент Codex), выполняй задачи строго по порядку и отмечай чекбоксы.

**Goal:** Полностью убрать C2 из репозитория и с production VPS, сохранив обычную публикацию цен и инвалидацию кэша сайта.

**Architecture:** Часть A выполняет агент: один PR, по коммиту на задачу, без действий на production. Часть B выполняет человек-администратор вручную: сначала обратимое отключение, затем приёмка на естественных запусках, затем окончательная очистка. После удаления пайплайн работает из обычного git checkout в `/opt/aktau-sync`, а код обновляется командами из `ops/sync/README.md`.

**Tech Stack:** Go 1.27.3, Node 24.10 (CI), pnpm 10.32.1, Python 3, bash, systemd, GitHub Actions.

**Spec:** Отдельной спецификации нет. Требования заданы разделами «Решение», «Что удаляем» и «Что обязательно остаётся».

## Решение

Команда решила удалить C2 и всё, что с ним связано (2026-11-05).

В этом проекте C2 означает две вещи, и удаляются обе:
1. **SLA из Jira:** сходимость кэша сайта за 5 секунд после подписанного ответа 204, наблюдатель и ledger попыток.
2. **Root-инструменты выкладки:** `publisher-promotion.py`, policy, пины, read-only монтирование пайплайна, разовые root-шаги, сборка и промоушен через GitHub Actions.

Промоушен удаляется вместе с C2, поэтому план вводит ему простую замену: ручное обновление checkout. Обновить VPS самим промоушеном нельзя: `verify_baseline` требует publisher `ea3cf04`, а на проде `e50de25`, и вторая policy succession не поддерживается.

## Что обязательно остаётся

- **Инвалидация кэша сайта.** Это не C2: без неё сайт показывает старые цены до часа. - **Ускорение sitemap** из PR #83 в `frontend/src/app/sitemap.ts`.
- **Разделение `engine.Stage` и `staged.Publish`** в ingest.
- **Категория яиц `C2`.** Значение в `frontend/src/mocks/*.json` и `frontend/scripts/generate-mocks.mjs`, а также в фикстурах и словаре пайплайна не связано с этой темой. Не трогать.

- **`scripts/ops/prepare-recovery-operator.mjs` и его тест.** Это инструмент восстановления бэкапа.

## Global Constraints

- Агент не подключается к VPS и не работает с SSH-ключами, паролями и файлами `secrets/`. Часть B вводит человек вручную.
- Агент не мержит в `main` и не пушит в него. Результат Части A: один PR.
- Точные имена 9 джоб CI не меняются: `Contracts`, `Go Quality`, `Nest Reference`, `Frontend`, `Pipeline Quality`, `Security`, `PostgreSQL Integration`, `Ephemeral Staging`, `CI Gate`. Их проверяет `scripts/deploy/auto-gate.mjs`.
- Новых джоб не добавлять. В `CI Gate` остаётся проверка на 8 зависимых джоб.
- Миграций БД нет. Настройки Supabase и Vercel не меняются. `reader.dsn` использовал существующую роль API, поэтому отдельной роли БД для удаления нет.
- Каталог `frontend/` не меняется.
- Репозиторий публичный: никаких секретов, адресов серверов и значений из `.env` в коде, документах и PR.
- Запускать bash- и CI-скрипты на Linux или в WSL. Go-сборки используют `GOTOOLCHAIN=local`.
