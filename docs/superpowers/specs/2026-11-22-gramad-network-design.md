# Новая сеть Gramad: скрап, словарь, две сети в публикации

Дата: 2026-11-22. Роль: Backend 2 (решения — Owner). Предыдущий проект — «Данные Шымкента»
(`docs/superpowers/specs/2026-11-21-shymkent-data-design.md`, отчёты
`SHYMKENT_DATA_BASELINE_REPORT.md`, `SHYMKENT_MAGNUM_DICTIONARY_REPORT.md`, `SHYMKENT_END_TO_END_REPORT.md`).

## Зачем

В Шымкенте сейчас одна сеть — Magnum, поэтому сравнивать цены не с чем: в `/api/dashboard`
`matchedAcrossStores` равно 0, `priceSpreads` пуст, СЗПТ показывает цены одной сети. Gramad — местная
сеть Шымкента (с 2019 года, все филиалы в городе). Проект добавляет её второй сетью: скрап, словарь
(новые карточки и присоединение к карточкам Magnum), строка в реестре `stores`, публикация. Итог —
первый снимок с двумя сетями и сравнением цен в `/api/szpt` и `/api/dashboard`.

## Цели

1. Модуль скрапа `GRAMAD` на асинхронном ядре `pipeline/src/scrape/core`, команда `pnpm scrape:gramad`.
2. Весовые товары Gramad определяются правилом «слово КГ + код» (ниже); правило веса в трёх местах
   поддерживает обе сети.
3. Словарь Шымкента покрывает товары Gramad публикуемых категорий: часть присоединена к карточкам
   Magnum по штрихкоду, часть — решениями субагентов, остальное — новые карточки.
4. `GRAMAD` — строка в `stores`; `SYNC_STORES` по умолчанию `MAGNUM,GRAMAD`.
5. Сквозной прогон на проверенной одноразовой локальной PostgreSQL по порядку будущего production:
   снимок только с Magnum → новая миграция → снимок с двумя сетями без конфликтов strict-ingest →
   `/api/szpt` и `/api/dashboard` с двумя сетями.

  неё не обойтись, — остановка и вопрос Owner.
- Точки продаж Gramad на карте (`store_locations`) и цвет сети на карте (зона Frontend: сеть без цвета
  показывается нейтральным серым).

## Источник и разведка (итог)

Разведка проведена 2026-11-22 с разрешения Owner, без входа в аккаунты. Подробности доступа к данным
хранятся только локально.

- Собственный сайт сети каталога с ценами не имеет.
- Источник — страница Gramad в сервисе доставки **Glovo**, одна точка «Супермаркет GraMad». Сервис
  заявляет цены «как в заведении». Сверка с акционной листовкой сети: молоко «Бурёнкино» 2,5% 1,95 л —
  1273 и по акции 855 против 1259 и 880 в листовке; Coca-Cola 1 л — 695 в обоих сервисах доставки.
- Есть все нужные категории: молочные, яйца, овощи и фрукты, хлеб, крупы и макароны, сахар, соль,
  масло, чай и кофе; мясо и птица — только замороженные; рыба — только замороженные морепродукты.
- У товара есть код магазина (у упакованных — штрихкод EAN-13, у развесных — короткий внутренний
  код), название, цена, цена акции (отдельным полем), признак «нет в наличии», картинка.
- **Признака весового товара у источника нет**: тип продажи у всех товаров штучный, включая
  «КАРТОФЕЛЬ КГ». Развесной товар продаётся шагом в 1 кг, его цена — за кг; на это указывает только
  слово «КГ» в конце названия и короткий код.

## Подходы и решения Owner

**Источник.** Рассмотрены: (а) собственный сайт — каталога нет; (б) второй сервис доставки — богаче
данными (явный признак веса, цена за единицу, штрихкод), но в точках Gramad нет свежих категорий:
овощей, фруктов, яиц, мяса, хлеба, рыбы — группы СЗПТ по ним остались бы без сравнения; (в) Glovo —
полный набор категорий и цены как на полке, но без признака веса; (г) оба сервиса сразу — два файла
источника и вопрос, чья цена главная. **Выбрано (в)** решением Owner.

**Весовой товар.** Рассмотрены: (1) слово «КГ» в конце названия вместе с кодом не из 11–13 цифр;
(2) только слово «КГ»; (3) не считать весовыми никакие товары Gramad — тогда его овощи и мясо выпадают
из весовых групп СЗПТ. **Выбрано (1)** решением Owner. Это осознанное отступление от правила «весовые
только по флагам источника»: правило опирается на два поля самого источника (название и код),
а не на догадку по смыслу названия.

**Присоединение к карточкам Magnum.** Рассмотрены: (1) сначала детерминированно по штрихкоду EAN-13,
остальное — субагенты Haiku; (2) только субагенты, штрихкод — подсказка. **Выбрано (1)** решением Owner.

**Дашборд и СЗПТ.** Go не меняется (см. «Не цели»): группы СЗПТ определяются по названию карточки и
берут минимальную цену по сетям; `priceSpreads` считается по карточкам с предложениями двух сетей;
весовые и штучные предложения одной карточки разводятся при публикации (`isolateForPublish`), а
присоединение весового товара к штучной карточке запрещается кодом (часть 2).
Корзина — отдельная задача (решение Owner).

**Части.** Рассмотрены: три части; две (код отдельно, данные и прогон отдельно) — тогда строка
`GRAMAD` в `stores` попадёт в `main` без словаря Gramad, и синхронизация только с Magnum начнёт падать
(`required_source_missing`); один PR — слишком большой дифф. **Выбрано: три части** решением Owner.
Строка `GRAMAD`, правило веса и словарь Gramad попадают в `main` одним PR (часть 2).

## Правило веса Gramad

Парсер Gramad ставит `rawPayload.isWeighted = true` и `rawPayload.priceUnit = 'kg'` ровно тогда, когда
выполнены **оба** условия:

1. последнее слово названия — «кг» без учёта регистра, отделённое пробелом, и перед ним не стоит число
   («КАРТОФЕЛЬ КГ» — да; «Сахар 1 КГ», «Рис 0,5кг», «Мука 2 кг» — нет). Проверка — по словам названия
   (разбиение по пробелам), без `\b` (он не работает после кириллицы);
2. код товара у источника — не из 11–13 цифр (код из 11–13 цифр — штрихкод упакованного товара: EAN-13 или код без ведущей цифры; решение Owner после первого прогона).

Если выполнено ровно одно условие, товар считается штучным, получает `rawPayload.weightAmbiguous = true`
и попадает в счётчик спорных в `sourceStats` прогона. Цена весового товара — за 1 кг, как отдаёт
источник (умножения нет; проверка «×1000» — в тестах).

В остальных трёх местах правило — общее для обеих сетей и явным списком сетей:
`storeCode ∈ {MAGNUM, GRAMAD}` и `rawPayload.isWeighted === true`; `basisGrams` 1000. Неизвестная сеть
— не весовая (fail-closed).

## Части

### Часть 1. Скрап Gramad

Ветка от свежего `origin/main`, свой worktree, PR в `main`. БД, миграций и `stores` в этой части нет.

1. **Техническая разведка** (отдельное «да» Owner): как источник отдаёт полный список товаров
   категории (постраничность, лимиты). Результат — только в локальных заметках; в репозиторий — код.
2. **Модуль** `pipeline/src/scrape/stores/gramad/` по образцу `magnum/`: `index.ts` (`StoreModule`,
   `storeCode: 'GRAMAD'`, `city: 'Shymkent'`; адрес API и идентификатор точки — в коде, как у Magnum;
   заголовки запросов и всё, похожее на токены, — только из локального `.env` вне git, без них скрап
   завершается понятной ошибкой до первого запроса; в `.env.example` — только имена переменных),
   `parse.ts`, `scope.ts` (`GRAMAD_SCOPE`: категории
   источника → `CategorySlug` и путь `sourceCategoryPath`), `coverage.ts` (пустой файл или слаг без
   товаров — отказ, прежний файл сохраняется).
3. **Отображение товара** в `SourceProduct`: `sourceProductId` из кода магазина (`gramad_<код>`);
   `price` — цена акции, если она есть и меньше обычной, иначе обычная; `oldPrice` — обычная при акции,
   иначе `null`; цены — целые тенге (`Math.round`), неположительная цена — ошибка товара; `brand: null`;
   `imageUrl`; `rawPayload`: код, `barcode` (код, если это ровно 13 цифр, иначе `null`), `isWeighted`,
   `priceUnit`, `weightAmbiguous`, обычная цена и цена акции, категория источника. Товары «нет в
   наличии» пропускаются. Неизвестная форма ответа — ошибка (а не тихий пропуск).
4. **`GRAMAD_SCOPE`**: только категории источника, которые соответствуют публикуемым слагам
   (`DEFAULT_PUBLISH_CATEGORIES`): `milk`, `dairy`, `eggs`, `bread`, `meat` (замороженное мясо и птица),
   `vegetables` (овощи, зелень, фрукты), `groats`, `sugar`, `oil`, `salt`, `tea-coffee`, `fish`
   (замороженные морепродукты). Сладости, напитки, колбасы, алкоголь, табак, непродовольственные — не
   скрапятся. Список составляется по разведке и первому прогону.
5. **Регистрация**: `STORE_CODES = ['MAGNUM', 'GRAMAD']` (реестр модулей pipeline); `cli/scrape.ts` —
   `GRAMAD` со своей проверкой покрытия; `package.json` — `scrape:gramad`; `agent/bundle.ts`
   `IMAGE_ORDER = ['MAGNUM', 'GRAMAD']`. `SYNC_STORES` по умолчанию остаётся `MAGNUM`.
6. **Тесты на синтетических фикстурах** (без реальных дампов): весовой товар (КГ + короткий код,
   цена за кг без ×1000); «Сахар 1 КГ» с EAN-13 — штучный; «… КГ» с EAN-13 — штучный и спорный;
   короткий код без «КГ» — штучный и спорный; «кг» в нижнем регистре и после кириллицы; цена акции;
   «нет в наличии» пропущен; неположительная цена и неизвестная форма ответа — ошибка; проверка покрытия.
7. **Живой прогон** `pnpm scrape:gramad` (отдельное «да» Owner, один прогон): товаров, весовых,
   спорных, по слагам, ошибок, повторов, 429/5xx, время. Файл — локальный `data/sources/gramad.json`.

**Готово (часть 1):** `pnpm test`, `pnpm typecheck`; локальный CI `pipeline,security,guard`; отчёт
`docs/production/reports/SHYMKENT_GRAMAD_SCRAPE_REPORT.md` со статистикой прогона.

### Часть 2. Словарь Gramad и сеть в реестре

Ветка от `origin/main` после слияния части 1, свой worktree, PR в `main`.

**Присоединение по штрихкоду** (`dict:prepare`, общее для любой сети):

- Для сети `X` строится индекс EAN-13 → карточки по файлам источников других сетей, уже
  сопоставленных в словаре (`data/sources/<store>.json`; у Magnum штрихкоды — `rawPayload.barcodes`):
  штрихкод → идентичность товара → карточка в `dictionary.products`. Нет файла источника другой
  сети — выход с кодом 2 и понятной ошибкой (без тихого отказа от шага).
- Товар `X` с EAN-13 присоединяется без модели, если штрихкод ведёт **ровно к одной** карточке, в этой
  карточке ещё нет товара `X`, размер и жирность из названия не противоречат атрибутам карточки
  (`sizeConflict`) и ни товар, ни члены карточки не весовые. Иначе товар уходит субагентам; штрихкод,
  ведущий к нескольким карточкам, считается отдельно.
- `dict:prepare` словарь не меняет: пишет найденные пары в файл заданий рядом с батчами;
  `dict:apply-decisions` применяет их вместе с решениями субагентов (`--check` проверяет и их).
  Статистика: присоединено по штрихкоду, штрихкод ведёт к нескольким карточкам, отказ по размеру.

- Штрихкоды с префиксом 20–29 (внутренние коды магазинов, например у штучных яиц) в индекс не
  входят: они не глобальные и у разных сетей могут совпасть случайно (решение исполнителя спецификации).

**Весовой признак при присоединении (новая проверка в коде).** Сейчас от присоединения весового товара
к штучной карточке (и наоборот) защищает только строка промпта, а отделённый при публикации весовой
участник сохраняет название и размер карточки — «Рис 800 г» с ценой за кг попал бы в штучную группу
СЗПТ и в корзину. Поэтому: у кандидата в батче есть признак `weighted` (карточка весовая, если весовые
её участники по файлам источников); `applyDecisions` отвергает присоединение, если весовой признак
товара и карточки различается (счётчик `rejectedWeight`), и создаёт новую карточку. Тест — в части 2.

**Субагенты:** остальные товары — тем же путём (`dict:prepare GRAMAD` → по одному субагенту Haiku
на батч → `dict:apply-decisions GRAMAD --check` → `dict:apply-decisions GRAMAD` → `pnpm dict:apply`).
В общий промпт добавляется правило: названия источника бывают заглавными буквами и с сокращениями
упаковки («ТВА», «П/Б», «СТ»); `displayName` — обычным регистром, без сокращений упаковки.
Источник товаров — локальный `gramad.json` прогона части 1 (нового живого скрапа нет); файл Magnum —
локальный `magnum.json` последнего прогона.

**Ревью агентом:** все присоединения субагентов к карточкам Magnum; случайные 10% присоединений по
штрихкоду; все новые карточки `eggs`, `milk`; случайные 10% остальных новых (сид записать).
Ошибки — правкой решений и повторным применением от копии словаря или `moveCategory` в
`overrides.json`. При изменении фильтров — новая миграция таксономии через `pnpm taxonomy:sql`.

**Сеть в реестре и правило веса** (меняются вместе, одним PR):

- Новая миграция `<дата-время>_shymkent_gramad_store`: строка `stores` (новый UUID, `code 'GRAMAD'`,
  `name 'Gramad'`, `"logoUrl" NULL`, `"sortOrder" 20`, без `store_locations`) и пересоздание
  `offer_price_basis` с правилом `WHEN 'MAGNUM', 'GRAMAD' THEN …isWeighted…`; гранты, отзыв прав и
  охранные проверки RLS — как в базовой миграции. Существующие миграции не меняются.
- `pipeline/src/mapping/weight.ts` — то же правило; `ops/postgres/szpt/offer_price_basis_check.sql` —
  то же правило и ссылка на новую миграцию как на последнюю, определяющую представление.
- `scripts/ci/postgres.mjs` — цепочка миграций; `scripts/deploy/auto-gate.test.mjs` — список
  «не допускается автотранспортом» (allowlist не трогать).
- Зона Backend 1, минимальные правки (решение Owner): `backend-go/internal/ingestion/identity_integration_test.go`
  — бандлы теста должны соответствовать набору сетей в `stores` после новой миграции (учесть `GRAMAD`
  или убрать строку в подготовке теста; смысл теста не меняется); `backend-go/scripts/local-ingest-db.sh`
  — применять и новую миграцию. Другие правки в `backend-go/` — только с отдельного «да» Owner.
- `cli/sync.ts`: `SYNC_STORES` по умолчанию `MAGNUM,GRAMAD`; `ops/sync/README.md`,
  `ops/sync/aktau-sync.env.example`, `docs/data/SYNC_RUNBOOK.md` — то же.

### Часть 3. Сквозной прогон двух сетей

коммит), часть не добавляет.

1. Свежие живые скрапы `pnpm scrape:magnum` и `pnpm scrape:gramad` — каждый после отдельного «да»
   Owner. Новые товары обеих сетей — в словарь тем же путём; при изменении фильтров — миграция

4. **Шаг B — выкатка Gramad:** миграция части 2 (и таксономии, если есть) →

   `canonical_merge_conflict` и `canonical_split_conflict` (в отчёте ingest — `mergedCanonical` и
   `splitCanonical`). Обоснование по коду: товары Gramad — новые идентичности без прежних канонических
   id, а существующие карточки Magnum не сливаются и не делятся; конфликт возможен только при ручной
   правке карточек (`split` в `overrides.json`) между шагами A и B. Если конфликт есть — диагностика пробным `-recluster`, запись в отчёт и вопрос
   Owner, а не молчаливый `-recluster -apply`. Затем `-apply` → `ANALYZE`.
5. Локальный Go API на этой БД (роль чтения). Проверки:

## Риски

- **Одна точка Gramad.** Цены одной точки выдаются за цены сети; у других филиалов они могут
  отличаться.
- **Цены сервиса доставки.** Совпадение с полкой проверено на нескольких товарах; источник может
  ввести наценку без предупреждения.
- **Правило веса по названию и коду** держится на том, как сеть называет развесные товары. Счётчик
  спорных в каждом прогоне — сигнал, что правило перестало работать.
- **Только замороженное мясо и морепродукты у Gramad.** В мясных группах СЗПТ возможны пары
  «свежее у Magnum / замороженное у Gramad» в одной группе (группа общая, карточки разные).
- **Первый снимок с двумя сетями в production** пройдёт только при порядке: миграция части 2 →
  словарь → бандл с двумя сетями; часть 3 это репетирует.

## Оставлено исполнителю

- Точные лимиты запросов модуля Gramad (не выше, чем у Magnum) и постраничность.
- Формат `sourceCategoryPath` и состав `GRAMAD_SCOPE` по итогам разведки.
- Имя и формат файла пар по штрихкоду в каталоге заданий, точные имена счётчиков статистики.
- Точная дата-время в имени миграции, UUID строки `GRAMAD`.
- Как именно `dict:prepare` находит файлы источников других сетей (по сетям в `dictionary.products`
  или по `STORE_CODES`) — при условии явной ошибки, если нужного файла нет.
