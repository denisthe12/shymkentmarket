# SCRUM-25: раздел «СЗПТ» — дизайн

> Historical design or rollout plan. For current deployment and rollback, see the [Frontend VPS runbook](../../production/FRONTEND_VPS_DEPLOYMENT.md).

Дата: 2026-11-12. Статус: согласован в чате по частям, ждёт проверки спецификации.

## Зачем

Jira [SCRUM-25](https://cryptonite.atlassian.net/browse/SCRUM-25) просит категорию СЗПТ
(социально значимые продовольственные товары). Команда 2026-11-11 уточнила задачу
(`ADILBAGA_SZPT_TEAM_SUMMARY_2026-11-11.md`, не в репозитории): отдельный раздел, где пользователь выбирает вид
продукта, видит реальные фасовки и сравнивает **две цены одновременно**:

1. цену упаковки, ₸ — сколько платить на кассе (главная цифра);
2. цену за одинаковое количество, ₸/кг, ₸/л или ₸/10 шт — подсказку, насколько выгодна фасовка.

«Самая дешёвая упаковка» и «самая выгодная фасовка» — разные понятия, сервис их не смешивает и не навязывает
бо́льшую упаковку. Автоподбора «самого дешёвого бренда» из исходного текста тикета нет: решение команды его заменяет.

Решения пользователя (2026-11-11/12):

- состав MVP — 10 групп команды: рис, гречка, сметана, творог, сыр, молоко, кефир, подсолнечное масло,
  яйца I категории, сливочное масло;
- товары отбираются **по критериям приказа**: числовые условия (жирность, категория яиц) строго, при отсутствии
  признака товар не входит; тип продукта, который название не подтверждает, — через список исключений;
- для молока и кефира фасовка в граммах считается равной миллилитрам (1 г = 1 мл), пересчёт — в ₸/л;
- устройство — **отдельный API** (вариант A), а не виртуальная категория и не метка в pipeline;
- весовые товары без фасовки в MVP не входят;
- релиз — сначала API, потом фронт.

Основание перечня: приказ МТИ РК от 23.12.2025 № 362-нқ (31 позиция, действует с января 2026). Перед релизом
сверить действующую редакцию на adilet.zan.kz (в источниках упоминается приказ от 05.02.2026 № 79-нқ).

Не входит: фильтр или поле «Мой бюджет», корзина и оптимизация покупок, автоподбор на сумму, остальные 21 позиция
перечня, весовые товары, изменения parser/snapshot/cron, цена за единицу на странице товара, изменения Voice/Siri,
новая вкладка в нижней панели, события pilot-аналитики.

Найденные проблемы данных, которые дизайн учитывает:

- ошибки парсера фасовки: «Кефир Био 750 г» → `weightGrams: 1`, «…970л» без объёма — защита минимальной фасовкой;
- весовые товары («… вес», «весовой») без фасовки, цена у них за кг (`Сыр … Березка 50% вес` — 5 067 ₸) —
  исключаются;
- крупные фасовки сыра (1,5–13 кг) — реальные цены за головку (LAIME 6 кг — 45 600 ₸ = 7 600 ₸/кг), пересчёт верен;
- яйца поштучно (`Яйцо куриное С1`, 69 ₸, `packageCount: 1`) — реальная поштучная продажа, 690 ₸/10 шт;
- творог не совпадает между сетями ни разу, яйца — тонкая группа; это свойство данных, не дефект раздела.

Matching уже держит разные фасовки разными SKU: `volumeMl, weightGrams, packageCount, fatPercent` должны совпасть
(`pipeline/src/agent/match.ts:27`). У канонического товара одна фасовка на все предложения, поэтому цена за единицу
каждого предложения считается однозначно.

## Часть 1. API

Существующие `/api/products`, `/api/categories`, `/api/categories/{slug}/filters`, `/api/dashboard`, Voice и их DTO
не меняются. Оба новых endpoint-а — GET, читают последний опубликованный снапшот тем же `snapshotReader`, что каталог.

### `GET /api/szpt`

```json
{
  "groups": [
    { "slug": "rice", "name": "Рис", "unit": "kg", "sizes": [400, 700, 800, 900, 1000, 3000, 5000], "count": 77 },
    { "slug": "milk", "name": "Молоко", "unit": "l", "sizes": [400, 450, 500, 900, 950, 1000, 1950], "count": 122 },
    { "slug": "eggs", "name": "Яйца I категории", "unit": "10pcs", "sizes": [1, 10, 30], "count": 5 }
  ]
}
```

- Порядок групп фиксирован: как в таблице раздела «Группы».
- Группа без товаров в текущем снапшоте не возвращается (как категории).
- `unit` ∈ `kg | l | 10pcs`.
- `sizes` — различные фасовки товаров группы в наличии, по возрастанию, в базовой единице группы
  (граммы, миллилитры, штуки). Для молока и кефира граммы входят в тот же список как миллилитры.
- `count` — число товаров группы в наличии.

### `GET /api/szpt/{group}/products`

Параметры: `size` (повторяемый, OR), `sort` ∈ `price_asc | unit_price_asc` (по умолчанию `price_asc`),
`limit` (1–100, по умолчанию 24), `offset` (≥ 0). Те же правила разбора, что у `/api/products`:
одиночные `sort/limit/offset`, целые десятичные.

Ответ — массив товаров в формате каталога (`catalog.Product`) с двумя добавленными полями:

```json
{
  "id": "…", "name": "Рис Кызылординский 800 г", "brand": null,
  "category": { "slug": "groats", "name": "Крупы, макароны, мука" },
  "imageUrl": null, "attributes": { "weightGrams": 800 },
  "minPrice": 600,
  "unitPrice": { "value": 750, "unit": "kg" },
  "offers": [
    { "storeCode": "DINA", "storeName": "Dina Market", "price": 600, "oldPrice": null,
      "unitPrice": { "value": 750, "unit": "kg" } }
  ],
  "snapshotAt": "2026-11-11T01:00:51.947Z"
}
```

- `unitPrice` товара — цена за единицу предложения с `minPrice`; `offers[].unitPrice` — своя у каждого предложения.
- Формулы (размер `s` — фасовка товара в базовой единице группы):
  - `kg`: `price × 1000 / s`;
  - `l`: `price × 1000 / s` (для молока и кефира `s = volumeMl`, иначе `weightGrams`);
  - `10pcs`: `price × 10 / s`.
- `value` округляется до 2 знаков (half up) только в ответе. Сортировка в SQL — по точному `numeric`.
- `unitPrice` в контракте nullable (запас для весовых товаров второй фазы); в MVP всегда заполнен,
  потому что товар без фасовки в группу не входит.
- Сортировка: `price_asc` — `min_price, id`; `unit_price_asc` — точная цена за единицу лучшего предложения, затем
  `min_price`, затем `id` (`COLLATE "ru-x-icu"`, как в каталоге). Порядок стабилен для «Показать ещё».
- Ошибки: неизвестная группа → 404 `ErrNotFound`; неизвестный параметр, повтор одиночного параметра, `size` не из
  `sizes` группы, неверный `sort/limit/offset` → 400 `ErrInvalidQuery`. Формат ошибок — как у каталога.

### Код

- `backend-go/internal/szpt/` — модели (`Group`, `UnitPrice`, `Product`), интерфейс репозитория, упорядоченный
  список 10 групп с правилами (slug, имя, единица, категория, шаблоны, жирность, фасовка) — источник порядка, 404
  и правил отбора.
- `backend-go/internal/postgres/szpt.go` — SQL групп и товаров. Карточки собираются тем же кодом, что каталог
  (общие `productBaseSQL`/`offersSQL`-хелперы или выделенная из `products()` функция гидрации), чтобы формат
  не разъехался.
- `backend-go/internal/httpapi/` — два маршрута рядом с `/api/products`, разбор запроса, ответы.
- `contracts/openapi.yaml` + примеры в `contracts/examples/` — два пути и схемы.
- Миграций и изменений в `backend/prisma` нет. API-роль читает те же таблицы, что каталог.

## Часть 2. Группы

Правила — один упорядоченный Go-список в `backend-go/internal/szpt`, который передаётся в SQL параметром
(`jsonb_to_recordset($1)`), — по смыслу как слоты корзины в `backend-go/internal/postgres/dashboard.go`, но без второй
копии списка в SQL: порядок, 404 и шаблоны берутся из одного места, а значения не склеиваются в текст запроса.

Общие правила для всех групп:

- товар в наличии в текущем снапшоте (`o."inStock" AND o.price > 0`);
- категория товара совпадает с категорией группы;
- название подходит под шаблон группы и не подходит под её исключения;
- фасовка известна (`jsonb_typeof = 'number'`) и не меньше минимума группы;
- в названии нет `вес` как отдельного слова и нет `весов` — у таких товаров цена за кг;
- где у группы задан диапазон жирности, `fatPercent` должен быть числом в диапазоне (включительно);
- безлактозное и низколактозное (`безлакт`, `низколакт`) исключаются в группах молоко, кефир, сметана, творог.

Регулярки — регистронезависимые (`~*`), **без `\b`, `\m`, `\M`**: на кириллице они ненадёжны (урок SCRUM-19).
Граница слова задаётся явно классом букв: «вес» — `(^|[^а-яё])вес([^а-яё]|$)`, «солёное» —
`(^|[^а-яё])сол[её]н`. Регистронезависимый `~*` по кириллице уже работает в проде (слоты корзины, `'^молоко '`).
Исключения пишутся так, чтобы не задевать бренды и топонимы: «Савушкин продукт», «Краснодарский» рис —
такие названия входят в фикстуру как обязательные «входит».

Осознанные допущения:

- «Камолино» без «длиннозерный» входит в рис: среднезерный, обычно относится к круглому;
- яйца С0 («отборные») не входят: по приказу только I категория (С1);
- продажа яиц поштучно входит, `₸/10 шт = price × 10`;
- регулярки отлаживаются на тестовой фикстуре из реальных названий; при расхождении с таблицей правит тест,
  а не догадка.

## Часть 3. Фронт и навигация

- Маршрут `frontend/src/app/[lang]/(site)/szpt/[group]/page.tsx`: SSR как у `/collections/[slug]` — группы и первая
  страница товаров в HTML, дальше TanStack Query на клиенте. `/[lang]/szpt` → redirect на первую группу из
  `/api/szpt`; неизвестная группа → страница 404.
- Server-side запросы помечены тегом `catalog-data` — после публикации снапшота их сбрасывает существующая
  ревалидация (`app/internal/revalidate`).
- Вход: первая плитка в `CategoryTiles` на странице каталога — «СЗПТ» / «ӘМАТ», ссылка на `/szpt`, свой цвет
  (не из ротации категорий, не зелёный — он занят «выгоднее»). Плитка показывается, только если `/api/szpt` вернул
  хотя бы одну группу.
- Страница группы:
  - h1 «Социально значимые продукты»; подзаголовок «10 позиций из перечня СЗПТ (приказ МТИ РК № 362-нқ).
    Цены сетей на {дата снапшота}» — явно не весь перечень;
  - чипы групп (одиночный выбор = переход по пути), на мобильном горизонтальная прокрутка;
  - чипы «Фасовка» (множественный выбор) только из `sizes`; подписи форматирует фронт: `400 г`, `1 кг`, `900 мл`,
    `1,95 л`, `10 шт`; для молока и кефира — `мл`/`л`; URL `?size=800&size=1000`;
  - сортировка из двух вариантов: «Дешевле за упаковку» (по умолчанию, без параметра в URL) и
    «Выгоднее за кг / л / 10 шт» (`?sort=unit_price_asc`);
  - «Показать ещё», загрузка, ошибка и пустой результат — существующие компоненты категории.
- Карточка: `ProductCard` получает необязательное свойство `unitPrice`. Главная цифра — цена упаковки как сейчас;
  под ней мелко `840 ₸/кг` (округление до целых тенге при отображении). Без `unitPrice` строки нет — ни «0 ₸/кг»,
  ни прочерка. Вне раздела карточка не меняется.
- Фронт не агрегирует предложения и не пересчитывает цены — только форматирует значения API.
- Тексты ru/kk — `i18n/ru.json`, `i18n/kk.json`; данные для тестов и локальной разработки — `api/mockAdapter.ts`;
  sitemap — `/szpt/{group}` для каждой группы на обоих языках; метаданные и хлебные крошки — как у категории.

### Релиз

API раньше фронта: Vercel выкатывает `main` сразу, плитка без API вела бы на ошибку.

1. **PR 1 — API и контракт** (`backend-go`, `contracts/`, эта спека и план). CI зелёный → merge.
2. **Релиз API** ручным путём, как `a08ff71` (`docs/production/reports/GO_1_27_4_API_RELEASE_REPORT.md`):

### Готово, когда

- раздел доступен из каталога на ru и kk, 10 групп (минус пустые в снапшоте);
- фасовки — только реально существующие у группы;
- на карточке одновременно цена упаковки и пересчёт с правильной единицей; без фасовки пересчёта нет;
- обе сортировки работают, пример 420 ₸/500 г vs 710 ₸/1 кг проходит;
- разные фасовки и несовместимые характеристики не склеены;
- каталог, поиск, Voice, dashboard и их DTO не изменились (существующие тесты зелёные);
- фильтра «Мой бюджет» нет.

## Вторая фаза (не в этой задаче)

- весовые товары: правило «цена = за кг» с отдельной пометкой;
- остальные позиции перечня: мука, рожки, сахар, хлеб; затем мясо, птица, овощи, яблоки; рыба, чай и соль требуют
  расширения publish scope и миграции категорий;
- pipeline: «десяток» → `packageCount: 10`, объём вида `970л`;
- цена за единицу на странице товара.
