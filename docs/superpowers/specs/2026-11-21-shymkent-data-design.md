# Данные Шымкента: Magnum в публикации, свой словарь, без Актау

Дата: 2026-11-21. Роль: Backend 2 (решения — Owner). Предыдущий этап: асинхронные парсеры и модуль
Magnum (`docs/superpowers/specs/2026-11-20-async-scrapers-core-design.md`, отчёт
`docs/production/reports/SHYMKENT_MAGNUM_ASYNC_SCRAPERS_REPORT.md`).

## Зачем

Репозиторий Шымкента скопирован из Aktau Market. В нём до сих пор сети, данные, миграции,
документы и словарь Актау, а единственная настоящая сеть Шымкента — Magnum — есть только в
`pipeline/` и до публикации не доходит. Цель — чтобы цены Magnum проходили путь
скрап → sync → ingest → снимок → `/api/szpt` на данных Шымкента, а репозиторий (публичный)
больше не содержал данных Актау и внутренних заметок о его источниках.

Сейчас каждая новая сеть требует правки публичного контракта, Go, фронтенда и миграции. Проект
делает список сетей данными, чтобы следующие сети Шымкента подключались без такой правки.

## Цели

1. Код сети — открытая строка с проверкой формата; список сетей — строки таблицы `stores`.
2. Одна начальная миграция Шымкента вместо двенадцати унаследованных; в ней нет строк и адресов Актау.
3. Из кода, тестов, контракта, данных и документов убраны сети Актау `DINA`, `DANA`, `FIX_PRICE`, `ANVAR`.
4. Magnum публикуется: строка в `stores`, правило весового товара, `SYNC_STORES`.
5. Новый словарь и таксономия Шымкента, собранные субагентами через обобщённый `store-match`.
6. Группа СЗПТ «Яйца I категории» находит товары Magnum без правки правила в Go.
7. Сквозной прогон на проверенной одноразовой локальной PostgreSQL до `/api/szpt`.

## Не цели

- Переименование ролей и инфраструктуры `aktau_*` (`aktau_api_reader`, `aktau_ingest_writer`,
  `aktau_retention_writer`, systemd-юниты `ops/sync/aktau-sync*`, мониторинг, деплой). Это
  отдельная задача вместе с созданием настоящей БД Шымкента. Здесь эти имена остаются как есть.
- Точки продаж Magnum на карте: адреса — отдельная одобренная работа. Строка `stores` без `store_locations`.
- Сопоставление между сетями: сеть пока одна. Обобщённый `store-match` к этому готов, но
  проверяется только на одной сети.
- Группа СЗПТ «Рыба (лещ, карась, судак, карп, сазан)»: такой рыбы на складе Magnum нет, группа
  остаётся пустой. Правило не меняется.
- Production, хостинговая БД, деплой, push релизных веток. Включение релизных шлюзов.

## Анти-цели (провал, даже если «работает»)

- В репозитории (код, документы, тексты коммитов и PR) появилось описание способа получения данных
  источника, токены, адреса инфраструктуры.
- Данные Актау использованы как основа данных Шымкента (словарь, scope, overrides, фикстуры).
- Релизный шлюз Актау стал разрешающим для Шымкента (например, новые миграции попали в allowlist автодеплоя).
- Тесты сравнения нескольких сетей удалены вместо перевода на синтетические сети.
- Метрики получили неограниченное число меток из-за открытого кода сети.

## Подходы

**Миграции.** Рассмотрены (1) новые миграции поверх унаследованных: удалить строки Актау,
пересоздать тип — цепочка и закреплённые хэши релизных скриптов не меняются, но свежая БД Шымкента
сначала получает данные Актау; (2) новая начальная миграция. **Выбрано (2)** решением Owner: БД
Шымкента ещё нет, применять в production нечего, итог самый чистый. Цена — правка тестов и списков
в `scripts/deploy/` (зона Backend 1).

**Код сети.** Рассмотрены (1) закрытый список `[MAGNUM]` — мелкая механическая правка, но каждая
следующая сеть снова меняет контракт, Go, фронтенд и миграцию, а тесты сравнения сетей теряют
второй код; (2) открытая строка с проверкой формата и таблицей `stores` как реестром.
**Выбрано (2)** решением Owner: контракт меняется сейчас в любом случае, пусть последний раз.

**Словарь.** Рассмотрены (А) обобщить существующий путь субагентов `store-match`
(`anvar-prepare`/`anvar-apply`) на любую сеть, добавив в решение название и бренд карточки;
(Б) субагенты отвечают в формате Gemini, дальше `classify` → `agent:match` — второй путь для
межсетевого сопоставления и пересборка словаря целиком; (В) без модели, детерминированно — карточки
с исходными названиями, яйца пришлось бы чинить правилом в Go. **Выбрано (А)** решением Owner;
субагенты — Haiku, запускает их агент-исполнитель, ключ Gemini не нужен.

### Часть 2. Словарь и таксономия Шымкента

**Обобщённый `store-match`:**

- `anvar-prepare`/`anvar-apply` заменяются на `pnpm dict:prepare <STORE>` и
  `pnpm dict:apply-decisions <STORE> [--check]`. Каталог заданий —
  `data/agent/<store>-match/` (в `.gitignore`). Повторный запуск готовит только товары, которых
  нет в словаре; источник — `data/sources/<store>.json`.
- Решение субагента расширяется: `{ id, category, match, confidence, displayName, brand }`.
  `displayName` обязателен (название карточки, если создаётся новая: «Тип Бренд характеристики
  размер», например «Яйцо куриное С1 Бренд 10 шт»); `brand` — строка или `null`.
- `applyDecisions`: новая карточка получает `name = displayName` и `brand`. Если размер или
  жирность, извлечённые из `displayName`, противоречат извлечённым из исходного названия, —
  карточка получает исходное название, счётчик `rejectedName`. Атрибуты по-прежнему только из
  исходного названия. Присоединение к существующей карточке — как сейчас.
- Промпт `store-match-prompt.md` — без города и сети в тексте (общий), с полями `displayName` и
  `brand`, правилом для яиц: в названии карточки — вид («куриное»/«перепелиное») и категория
  («С1», «С0», «Д1» …), если они есть в исходном названии или однозначно следуют из него.
  Весовые товары — без размера в названии.

**Сборка словаря (выполняет агент):**

1. Пустой словарь → `dict:prepare MAGNUM` → батчи по 40 → субагенты Haiku, по одному на батч,
   читают только свой батч и пишут только свой `decisions` → `dict:apply-decisions MAGNUM --check` →
   исправление невалидных батчей повтором субагента → `dict:apply-decisions MAGNUM`.
2. Выборочная проверка агентом: все карточки категорий `eggs`, `milk`, `dairy` и случайные 10%
   остальных; ошибки — через `overrides.json` (`moveCategory`) и `pnpm dict:apply`.
3. `pnpm taxonomy:sql` порождает новую миграцию таксономии `<дата>_shymkent_taxonomy`
   (`TAXONOMY_MIGRATION` указывает на неё); тест `taxonomy.test.ts` сверяет её со словарём.
