## Как построен словарь

Источник — локальный файл живого прогона 2026-11-21 (`capturedAt` 2026-11-21T11:32:42Z), 1403
товара. Новый живой скрапинг в этой части не запускался.

- `dict:prepare`: 1403 позиции, 36 пачек по 40 (последняя — 3), кандидатов 0 (словарь был пуст).
- Решения по пачкам готовили 36 субагентов (модель Haiku), по одному на пачку. `--check` прошёл с
  первого раза для всех 36, повторных попыток 0.
- Первое применение: `{"attached":0,"created":1403,"pendingSingletons":0,"rejectedOutsideCandidates":0,"rejectedSize":0,"sameStoreConflicts":0,"rejectedName":0}`.
- Итоговое применение после правок ревью (повтор от копии до применения): те же значения, `canonicals 1403 -> 1403`, перенесено 47, разделений 0, одобрений 0.

Итоговое ревью всей ветки выявило дубли брендов; они объединены правкой решений и повторным применением (см. ниже). Шаги 1–4 задачи 3 (подготовка пачек, субагенты, первое применение) выполнил управляющий агент
через запуск субагентов; шаги 5–8 (ревью, проверка СЗПТ, миграция, тесты) — исполнитель.

## Решения

- **Название и бренд в решении.** Новая карточка берёт `displayName` и `brand` из решения; атрибуты
  (размер, жирность) всегда из названия источника. Присоединение к существующей карточке её не меняет.
  Название отклоняется (`rejectedName`), если конфликтует по размеру или жирности либо у весового
  товара содержит размер.
- **Процедура части 3.** `dict:prepare` → решения → `dict:apply-decisions` (`--check`, затем применение) → `dict:apply` (правки категории из `overrides.json`). Повторный `dict:prepare` при оставшихся файлах решений требует `--force`.
- **`dict:prepare` не удаляет решения.** Без `--force` команда завершается с кодом 2, если уже есть
  `batch-*.decisions.json`: готовая работа не теряется при повторном запуске.
- **Исправление названий.** Через решения и повторное применение от копии до применения, а не
  правкой `dictionary.json` вручную.
- **47 переносов категории** — через `overrides.json` (`moveCategory`), таблица выше.
- **`taxonomy.test.ts`.** Проверка «без карточек — категории без фильтров» теперь строит миграцию от
  пустого словаря: последняя миграция уже содержит фильтры, и прежняя проверка противоречила
  смыслу теста, а не коду.
- **Foodmaster как бренд молочных карточек.** Это название производителя на этикетке; суббренды
  Lactel и «Легкое утро» свёрнуты в него. **Вопрос Owner:** оставить так или хранить суббренды
  отдельно.

## Риски

- **«4Life» читается как 4 л.** Общий `extractSize` (`pipeline/src/agent/units.ts`) даёт трём
  карточкам соли 4Life `volumeMl` 4000, у одной нет `weightGrams`. Общий код не менялся; исправление
  — отдельной задачей. У карточки 500 г только `volumeMl` 4000; сохранённые атрибуты придётся пересчитать после правки `units.ts`.
- **Молокосодержащие продукты в `milk`.** Группа СЗПТ «молоко» их исключает, но категория каталога
  их содержит.
- **Вес в `extractSize`.** «Рис Asyl Dan янтарь 2,5 гр» получает `weightGrams` 3 (в фильтре веса круп покажется как 3); многоштучные «5*80 гр» и «6*66 гр» берут вес одной порции. Оба случая — от общего `extractSize`, общий код не менялся.
- **Вес яиц.** Для диапазона берётся верхняя граница.
- **Маргарины и спреды в `dairy`.** Отдельной категории нет (36 карточек: 13 «Маргарин…» и 23 «Спред…» в начале названия).
- **Группа яиц.** Из-за зависимости от «1 Категория» в названии источника в ней всего 2 карточки.
- **Один снимок.** Словарь построен по одному снимку; новые товары части 3 пойдут тем же путём
  (`dict:prepare` → решения → `dict:apply-decisions`; последующий `dict:prepare` при оставшихся файлах решений требует `--force`).
- **Foodmaster.** Выбор бренда для молочных карточек ждёт решения Owner.
