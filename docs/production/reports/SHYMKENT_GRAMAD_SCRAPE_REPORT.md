## Что сделано

`pipeline/src/scrape/stores/gramad/`:

- `parse.ts` — `parseGramadSection(body, category)`: разбор ответа с листом категории в
  zod-схему; неизвестный тип блока или плитки, товар не той формы — ошибка с id категории.
  `sourceProductId` — `gramad_<код магазина>`; `price` — минимальная из положительных цен акции, если она
  больше 0 и меньше обычной, иначе обычная; `oldPrice` — обычная при акции, иначе `null`; целые
  тенге (`Math.round`); обычная цена ≤ 0 — ошибка с кодом товара; товары «нет в наличии»
  пропускаются, но учитываются в `seen`. `rawPayload`: `code`, `barcode` (код, если ровно
  13 цифр), `isWeighted`, `priceUnit`, `weightAmbiguous`, `regularPrice`, `promoPrice`,
  `categoryId`. `gramadWeight(name, code)` — правило веса (ниже).
- `scope.ts` — `GRAMAD_SCOPE`: 37 листов источника → 12 публикуемых слагов; порядок = приоритет
  при дедупликации; путь `[группа, подборка, лист]`.
- `index.ts` — `createGramadModule(env)`: один запрос на лист, постраничности у источника нет;
  лимиты `concurrency 2`, `rps 4` (максимумы 4 и 8 — ниже Magnum); заголовки запросов только из
  переменной окружения `GRAMAD_REQUEST_HEADERS` (JSON-объект в локальном `pipeline/.env`, вне
  git); без неё или с неверным значением фабрика падает с именем переменной до первого запроса.
  Адрес API и идентификаторы точки — в коде, как у Magnum (решение Owner).
- `coverage.ts` — отказ записи, если товаров нет или у слага из скоупа нет ни одного товара;
  прежний файл сохраняется.
- `stats.ts` — `sourceStats.weighted`, `sourceStats.weightAmbiguous` и
  `sourceStats.cappedSections` (листы, где источник отдал 100 и больше товаров — его предел на
  лист, возможна неполнота); CLI выводит счётчики и предупреждение со списком таких листов.

Регистрация: `STORE_CODES = ['MAGNUM', 'GRAMAD']`; `cli/scrape.ts` — таблица сеть →
`{ run, assertCoverage }`, модуль Gramad создаётся лениво, поэтому `scrape:magnum` работает без
переменной Gramad, поведение Magnum не изменилось; `package.json` — `scrape:gramad`;
`agent/bundle.ts` — `IMAGE_ORDER = ['MAGNUM', 'GRAMAD']`; `.env.example` — только имя
переменной без значения; тест границы ядра запрещает в `scrape/core` слова `gramad`, `glovo`,
`грамад`. `cli/sync.ts` (`SYNC_STORES` по умолчанию `MAGNUM`), `mapping/weight.ts`, миграции и
`ops/` не менялись.

## Правило веса Gramad

Признака весового товара у источника нет: тип продажи у всех товаров штучный. Парсер ставит
`isWeighted: true` и `priceUnit: 'kg'`, когда выполнены оба условия:

1. последнее слово названия — «кг» без учёта регистра, отделённое пробелом, и перед ним есть
   слово, которое не число («КАРТОФЕЛЬ КГ» — да; «Сахар 1 КГ», «Рис 0,5кг» — нет); без `\b`;
2. код товара — не из 11–13 цифр.

Ровно одно условие — товар штучный, `weightAmbiguous: true`. Цена весового — за 1 кг, как отдаёт
источник, без умножения.

**Изменение по итогам первого прогона (решение Owner).** Сначала условие 2 было «код не из
13 цифр». В первом прогоне 37 из 45 спорных товаров оказались упакованными товарами с кодом из
12 или 11 цифр (штрихкод без ведущей цифры): сыры, кефир, крупы, масло, чай. Owner решил считать
код из 11–13 цифр упакованным товаром. Поле `barcode` по-прежнему — только ровно 13 цифр.

## Решения исполнителя

- Постраничности у источника нет: лист приходит одним ответом. Поэтому вместо
  `parseGramadPage(…, page)` из плана — `parseGramadSection(body, category)`, задача модуля —
  один лист (план допускал смену курсора по итогам разведки).
- Предел источника — 100 товаров на лист. Модуль на нём не падает (иначе один большой лист
  блокировал бы каждый прогон); лист у предела виден в `cappedSections` и в логе.
- Соль и сахар у источника в одном листе «Соль и сахар» → слаг `sugar`; тест скоупа явно
  фиксирует, что своего листа у `salt` нет. Разнести соль и сахар — задача словаря (часть 2).
- Мука — в листе «Для выпечки» (`groats`). Мясо, птица и морепродукты у точки только
  замороженные; морепродуктов в наличии — один товар.

## Риски

- **Одна точка Gramad** — её цены выдаются за цены сети.
- **Правило веса по названию и коду.** Три развесных товара без «КГ» в названии считаются
  штучными с ценой, вероятно, за кг. В части 2 их нельзя присоединять к штучным карточкам; флаг
  `weightAmbiguous` — сигнал для ревью словаря. Рост счётчика спорных — признак, что сеть
  поменяла названия.
- **Предел 100 товаров на лист.** Сейчас ни один лист его не достигает (максимум 92); при росте
  ассортимента часть товаров листа пропадёт, это будет видно в `cappedSections`.
- **Коды из 11–12 цифр** не попадают в `barcode`, поэтому в части 2 такие товары не
  присоединятся к карточкам Magnum по штрихкоду — только решениями субагентов.
- **Порядок части 2.** После этой части `dict:prepare GRAMAD` уже принимается CLI, но `weight.ts` пока знает только Magnum: весовые товары Gramad были бы помечены штучными. В части 2 правило веса меняется до первого `dict:prepare GRAMAD`.
- **Мало рыбы и мяса** у точки (1 и 8 товаров) — сравнение в этих группах СЗПТ будет бедным.
- **Цены сервиса доставки** совпадали с полкой на проверенных товарах; наценка может появиться
  без предупреждения.
