# Защита скрапа от частичной выдачи источника

**Статус — READY_FOR_REVIEW.** Ссылка на PR и выводы GitHub Actions записываются отдельно.

Ветка `feat/scrape-drop-guard` от `main` `c2cd926` (merge PR #11). Роль: Backend 2.

## Зачем

Сквозной прогон 2026-11-22 (`SHYMKENT_GRAMAD_END_TO_END_REPORT.md`) шёл на 462 товарах Gramad против 599
часом раньше. Контрольный живой скрап 2026-11-23 (один прогон, «да» Owner) дал 590 товаров, ошибок 0:
из 137 пропавших вернулись 136. Провал был временным, причина неизвестна. Скрап при этом завершался
успешно: проверка покрытия отвергала только категории без единого товара. Порог ingest отвергает бандл
целиком (вместе с Magnum), а первый снимок с новой сетью не защищает — сравнивать не с чем.

Следствие для отчёта о сквозном прогоне: его числа СЗПТ и 197 общих карточек сняты на неполной выдаче
Gramad; на полной прогон не повторялся (NOT_RUN). Порог ingest в том прогоне был 50, в примере
настроек — 10.

## Что сделано

- `pipeline/src/scrape/accept.ts`: общая приёмка прогона для Magnum и Gramad. Ошибки запросов, покрытие,
  затем падение числа товаров более чем на 10% против прежнего файла. Любой отказ — выход 1, прежний
  файл не тронут. Битый прежний файл — предупреждение и запись нового; ошибка чтения файла — отказ.
- `--accept-drop`: разово принять сокращение. Аргумент запуска, а не переменная окружения, чтобы он не
  остался включённым. Ошибки и покрытие не обходит.
- `pipeline/src/scrape/stores/gramad/coverage.ts`: минимум товаров для 16 крупных разделов (около
  половины обычного объёма; например, макароны 45, рис и гречка 10, овощи 6). Категории, как и раньше,
  нужен хотя бы один товар. Действует и на первом прогоне.
- `docs/data/SYNC_RUNBOOK.md`: что делать при отказе, ручная сверка перед первым снимком.

Go, миграции, словарь и `daily-sync.sh` не менялись: обёртка уже берёт прошлый файл упавшей сети (выход 3).

## Ревью

Независимое ревью и повторная проверка правок (APPROVED); затем добавлен минимум для творога. Исправлено: минимум чая был завышен (норма 71, а не 108); минимумы по категориям
пропускали потерю целого раздела — заменены на минимумы по разделам; ошибка чтения прежнего файла больше не
отключает сравнение; уточнён runbook; добавлены тесты.

## Риски

- Если сеть надолго сократит ассортимент, скрап будет отказывать; после `SYNC_MAX_SOURCE_AGE_HOURS`
  `sync` остановится для всех сетей. Порядок действий — в runbook.
- Провал, который меньше 10% файла и меньше половины крупного раздела (или целиком в мелком разделе),
  проходит. Несколько таких подряд могут сложиться.
- Минимумы Gramad подобраны по двум полным прогонам (599 и 590). `--accept-drop` их не обходит.
- Связка CLI с приёмкой автотестом не покрыта (проверены типы и запуск с неверным аргументом).
