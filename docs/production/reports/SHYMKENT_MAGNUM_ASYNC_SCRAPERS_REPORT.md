## Что сделано

**Каркас** `pipeline/src/scrape/core/` (импортирует только `node:*`, `zod`, свои файлы и
`../../types.js`; без слов, привязанных к городу или магазину — проверяется тестом границы):

- `limiter.ts` — ограничение параллельности и темпа (rps).
- `limits.ts` — лимиты магазина из env `<STORE>_CONCURRENCY` / `<STORE>_RPS` в пределах максимумов модуля; мусор, ноль и дроби дают значение по умолчанию с предупреждением.
- `http.ts` — HTTP-клиент поверх встроенного `fetch`: повторы с backoff, `Retry-After` (секунды и HTTP-дата, ограничение `maxDelayMs`), общая пауза всех запросов после 429/503, таймауты, ответ 200 не-JSON — ошибка задачи.
- `queue.ts` — динамическая очередь задач (задачи порождают задачи).
- `run.ts`, `store.ts` — контракт модуля магазина и `runStore`: дедупликация товаров, путь категории из более ранней seed-категории, проверка итога категории, если источник его отдаёт, плоские `sourceStats`, остановка новых задач после первой упавшей; `assertNoErrors`.

**Модуль Magnum** `pipeline/src/scrape/stores/magnum/`:

- `parse.ts` — разбор страницы каталога: цены из тиынов в целые тенге, старая цена только если выше текущей; весовой признак и единица цены только из полей API (`measureUnit`), не из названия; позиции не в наличии и заглушки пропускаются; нераспознанная позиция, единица или код наличия — ошибка (fail-closed); проверка номера страницы.
- `scope.ts` — таблица из 38 листьев каталога Magnum → 12 публикуемых категорий сайта (`DEFAULT_PUBLISH_CATEGORIES`).
- `index.ts` — гостевой вход в начале прогона, проверка склада (даркстор 7001 для Шымкента), обход листьев до короткой или пустой страницы (итога категории API не отдаёт), предел 100 страниц на лист.
- `coverage.ts` — отказ записи, если товаров нет или у любой публикуемой категории их нет.

**Интеграция:** `SourceFile.city` — непустая строка (Go `ingest` поле не читает); код магазина
`MAGNUM` в `STORE_CODES`; `pnpm scrape:magnum` через реестр CLI; любая ошибка прогона или
непокрытая категория оставляет прежний `magnum.json`; ошибки подготовки прогона выводятся как
`[<STORE>] <сообщение>` с кодом выхода 1.

Постоянного ключа API нет, переменные `MAGNUM_*` для секретов не нужны. Токен гостя живёт
только в памяти прогона и заголовке запроса; в URL, логах, `describe` и сообщениях ошибок его
нет.

## GitHub Actions и изоляция

Push тематической ветки не подходит под фильтры `ci.yml` (только `main`, `integrate/full-stack`).
PR в `main` запускает `ci.yml`: `permissions: contents: read`, без `secrets.*`, PostgreSQL и
staging — одноразовые внутри раннера. `deploy-production.yml` срабатывает только по
`workflow_run` CI на `main`, а его задания с production закрыты условием
`github.repository == 'kiratonine/AdilBaga'`. Workflows, настройки репозитория, environments,
переменные и секреты в этой задаче не менялись.

## Решения

- Итога категории у API нет: лист считается скачанным на странице короче `size` или пустой; `total = null`, сверка с итогом для Magnum не применяется (решение Owner).
- Нераспознанная позиция останавливает прогон и файл не пишется: при новой структуре данных безопаснее отказ, чем частичный файл.
- После первой упавшей задачи новые запросы не ставятся: файл и так будет отвергнут, а продолжение нагружает отказывающий сервер.
- Лимиты по умолчанию 4 параллельных запроса и 8 rps: живой прогон без 429 за ~15 с, повышать незачем.
- В scope включены листья «Кулинарии» с мясом и рыбой; живой прогон показал, что мясные листья не добавляют уникальных товаров, рыбный — один.
- Принятые без исправления мелочи: тест на утечку токена не моделирует постоянную сетевую ошибку; текст сетевой ошибки в `http.ts` включается в сообщение задачи (токен в URL не передаётся); отложенные мелкие замечания ревью ядра не влияют на Magnum.

## Риски и ограничения

- Данные Magnum относятся к одному складу (даркстор 7001). Смена склада или формата API остановит прогон с ошибкой, прежний файл сохранится.
- По группам СЗПТ (приблизительная проверка правилами имён из Go): у группы «Рыба (лещ, карась, судак, карп, сазан)» товаров Magnum нет — склад их не продаёт; группа «Яйца I категории» не совпадает из-за требования «кур» в названии, тогда как товары называются «Яйцо … 1 Категория». Это работа второго проекта.
- Не входит в эту задачу (второй проект «Данные Шымкента»): `MAGNUM` в enum `StoreCode` Prisma и строка в `stores`, ветка `MAGNUM` в `isVariableWeight` / `offer_price_basis`, `SYNC_STORES`, словарь и таксономия, сквозной прогон через `sync`, БД и `/api/szpt`.
